# 灵犀挂件项目简介

## 项目解决的问题

学生在走路、通勤、实验操作、整理资料或情绪低落时，经常只需要一次很短的查询、记录、翻译或陪伴，但解锁手机、切换应用、重新输入背景和反复说明偏好会打断当前活动。现有助手也容易在下一次任务中忘记用户对结果的修改。

灵犀把低频复杂配置留在网页控制台，把高频轻交互交给随身挂件：按住说话、松开发送，通过简短屏显、灯光和语音获得回应。更重要的是，用户可以直接评价或修改结果，系统会把反馈沉淀为规则，并在后续相似任务中自动参考。

## 目标用户与场景

- 校园内需要频繁处理即时任务的本科生和研究生。
- 走路时查询简短信息或翻译一句话。
- 学习规划、资料整理等重复任务中保持固定输出习惯。
- 情绪不佳时获得低打扰、非诊断式的陪伴回应。
- 拍摄标识、菜单或资料截图并获得可播报的简短说明。

## 核心功能

1. 文字、语音和图片多模态任务输入。
2. Step 3.7 Flash 推理与 StepAudio 2.5 ASR/TTS。
3. 可观察的 Agent 规划、反馈记忆检索和模型调用链路。
4. 用户对每次结果进行正向评价或给出修改建议。
5. 全局偏好与相似任务规则自动召回，并进入后续生成上下文。
6. 记忆数量、召回次数、估算 token 成本、检索耗时和端到端延迟遥测。
7. OLED、RGB、按键和扬声器状态的网页数字孪生。
8. 上游失败自动兜底、断网演练、诊断导出和设备协议校验。

## 技术方案

- 前端：原生 HTML、CSS、JavaScript，流式消费 NDJSON Agent 事件。
- 服务端：Python 标准库 `ThreadingHTTPServer`、统一 Agent 编排和 Provider 路由。
- 模型：Step 3.7 Flash 原生多模态理解；StepAudio 2.5 ASR/TTS。
- 记忆：SQLite WAL，显式画像、结果反馈、全局/相似规则和召回统计。
- 设备：0.4-draft 事件协议，规定 16 kHz PCM、状态事件、序列号和 Bearer 设备令牌。
- 部署：Docker、Nginx、HTTPS、非 root 容器、健康检查和可回滚版本。

## 创新点

- 网页端不是一次性效果页，而是未来真实挂件的控制台和可观测层。
- 反馈不是简单的点赞统计，而是转化为后续任务可检索、可计量的规则。
- 同一套状态和事件语义同时驱动网页数字孪生与未来 ESP32-S3 硬件。
- 记忆成本、召回耗时和是否命中在控制台可见，便于验证“记住了是否真的更好”。
- 真实模型与本地兜底使用同一事件协议，现场网络异常不会卡死演示。

## 当前完成情况

已完成可公开访问的控制台、真实文字/视觉模型调用、语音链路、反馈记忆、用户隔离、运行遥测、断网降级、设备协议草案、容器部署和自动化测试。真实 ESP32-S3、I2S 音频、OLED/RGB 外设和 OTA 属于下一硬件阶段，不在当前页面中伪装为已完成。

## 使用方式与演示入口

- 在线演示：<https://lingxi.rainlei.xyz/demo>
- 系统控制台：<https://lingxi.rainlei.xyz/console>
- 公开仓库：<https://github.com/rain-lei/lingxi>
- 本地运行：安装 Python 3.10+，配置 `STEPFUN_API_KEY` 后执行 `python server.py`，访问 <http://127.0.0.1:8787/>。

推荐演示：先完成一个任务，对结果选择“需要调整”并输入“以后回答更简短，先给结论”；随后提交一个相似任务，观察 Agent Trace 中的反馈记忆命中、token 估算和新结果变化。
