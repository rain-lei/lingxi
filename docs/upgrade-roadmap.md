# 灵犀挂件持续升级路线

版本：Console 0.4
定位：灵犀由挂件终端、云端智能编排和网页控制台共同组成。网页端当前承担系统链路验证；真实硬件接入后，继续承担设备配置、调试、遥测、记忆管理和 OTA 运维。

## 1. 设计原则

1. **协议先于硬件**：浏览器数字孪生与 ESP32-S3 使用同一套状态和事件语义，接入实机时不重写业务编排。
2. **真实能力可辨认**：控制台明确标注“已运行、已定义、待联调”，不把模拟数据包装成硬件数据。
3. **现场可恢复**：模型、网络或音频异常均有超时、降级和诊断记录，任何一步失败都不能卡死整个演示。
4. **低认知负担**：挂件交互保持按住说话、松开发送；复杂配置和诊断集中在网页控制台。
5. **隐私可控制**：只保存用户主动表达的偏好，控制台提供查看、导出和删除入口。

## 2. 系统边界

```text
挂件终端 / 网页数字孪生
  └─ 语音、按键、图像、设备遥测
        ↓ WebSocket / HTTPS
LingXi Orchestrator
  ├─ 会话状态机与超时
  ├─ Provider 路由与降级
  ├─ 显式记忆与上下文
  └─ 设备事件适配
        ↓
Step 3.7 Flash / StepAudio 2.5 / SQLite
        ↓
OLED、RGB、扬声器、网页控制台
```

网页控制台不是临时演示壳，而是长期保留的设备管理面。挂件负责轻交互，控制台负责复杂配置和系统可观测性。

## 3. 当前版本：Console 0.4

已完成：

- Step 3.7 Flash 文本与图片理解，流式输出。
- StepAudio 2.5 ASR / TTS，浏览器语音作为兜底。
- 问答、陪伴、翻译三类 Agent 场景。
- 用户称呼与语速的显式 SQLite 记忆。
- 结果评价、修改规则沉淀和相似任务自动召回。
- 记忆检索耗时、估算 token、召回次数和反馈指标。
- 匿名访客隔离、应用层限流和统一安全响应头。
- 待机、倾听、思考、回应、断网状态机及 OLED / RGB 数字孪生。
- 上游失败自动降级、断网演练、运行遥测与诊断导出。
- HTTPS 部署、容器健康检查、GitHub 版本管理。

当前退出标准：

- 5 分钟演示流程连续运行 20 次，完成率不低于 95%。
- 文字首个可见反馈不超过 2.5 秒；视觉请求不超过 12 秒。
- 任何 Provider 异常在 5 秒内给出可理解反馈并恢复可操作状态。
- 桌面与 360 px 手机宽度均无横向溢出和不可点击控件。
- 仓库、前端响应和诊断文件均不包含 API Key。

## 4. 下一版本：Device 0.5

目标：把网页数字孪生替换为真实 ESP32-S3 输入输出，同时保留控制台并行观测。

| 模块 | 实现点 | 验收指标 |
|---|---|---|
| 设备连接 | WebSocket 鉴权、心跳、重连、序号去重 | 断网 10 秒内自动重连 |
| 语音上行 | INMP441 / I2S，16 kHz、16 bit、mono PCM 分片 | 噪声环境识别成功率 ≥ 85% |
| 屏幕反馈 | OLED 分页、截断、滚动和中英文布局 | 首段文字到达后 200 ms 内刷新 |
| 灯效反馈 | WS2812 状态映射、亮度限制、动画中断 | 状态切换无残留动画 |
| 音频下行 | 流式 TTS 缓冲、I2S 播放、打断 | 首包播放 ≤ 800 ms |
| 设备安全 | 一机一密、时间戳签名、密钥轮换 | 非法设备不能建立会话 |

Device 0.5 不加入大量新场景，优先把端到端链路做稳。

## 5. 场景版本：Field 0.5

目标：让灵犀从技术闭环进入校园与日常真实场景。

- 校园信息：校历、地点、活动和常用办事流程，通过可追溯数据源回答。
- 环境理解：拍照识别标识、菜单和物品，提供简短可播报结果。
- 陪伴安全：危机表达检测只做提示和求助引导，不替代专业服务。
- 弱网策略：请求排队、超时取消、离线提示音和最近能力缓存。
- 隐私中心：查看、纠正、导出、删除记忆；麦克风和摄像头有明确状态提示。
- 设备运维：固件版本、在线率、电量、温度、错误码和灰度 OTA。

退出标准：连续运行 8 小时无阻断故障；重连成功率不低于 99%；所有用户数据均可在控制台删除。

## 6. 产品化版本：Pilot 1.0

- 账号与设备绑定、多设备切换、访客模式。
- 记忆摘要、召回排序、保留期限和端到端审计。

- 外壳、续航、发热、佩戴安全和无障碍体验验证。

## 7. 持续优化节奏

每个迭代按同一闭环推进：

1. 从控制台遥测和真实测试记录中选择一个最大阻塞点。
2. 先补复现用例或协议测试，再修改实现。
3. 在数字孪生、真实 Provider、断网兜底三条路径上回归。
4. 记录成功率、首响应、完整耗时和恢复时间的前后变化。
5. 小版本上线，保留上一容器镜像和配置回滚点。

优先级始终是：**稳定性 > 端到端延迟 > 交互自然度 > 新功能数量**。

## 8. 黑客松展示结构

建议控制在 5 分钟：

1. 30 秒说明系统由挂件、编排服务和控制台组成。
2. 60 秒展示文字 / 语音流式问答与 OLED / RGB 状态同步。
3. 45 秒展示图片理解。
4. 45 秒展示显式记忆跨轮生效。
5. 45 秒运行设备自检并说明真实硬件替换点。
6. 45 秒进行断网演练与自动降级。
7. 30 秒展示硬件接入准备度与下一阶段指标。

评委在现场能直接看到四件事：能力真实可用、系统结构清楚、异常可以恢复、硬件路径已经定义。
