# 灵犀校园用户测试与证据记录

目标：在初赛截止前完成至少 5 名目标用户的短时体验，用脱敏、可复核的数据验证“真实问题”和“反馈记忆是否正确改善后续结果”。本文件是执行模板，不预填或虚构测试结论。

## 1. 测试对象与边界

- 对象：在走路、通勤、实验或学习间隙有高频短任务的在校学生。
- 时长：每人 8-10 分钟。
- 设备：手机或电脑浏览器，访问线上 Demo；真实挂件尚未联调时必须明确说明网页为控制台和数字孪生。
- 隐私：只记录匿名编号，不收集姓名、学号、联系方式；截图和视频需单独取得同意。
- 规则：测试主持人只读任务，不提示按钮位置或期待答案。

## 2. 固定测试流程

1. 让参与者口述一个真实、近期发生过的校园短任务。
2. 用文字或语音提交任务，观察能否独立完成。
3. 对结果选择“需要调整”，写下一条具体修改规则。
4. 提交一个相似任务，观察规则是否被召回、结果是否体现修改。
5. 上传一张不含隐私的校园图片，完成一次视觉理解。
6. 运行设备自检并询问参与者是否理解网页与未来硬件的关系。
7. 记录一条最希望改进的意见。

完成相似任务后点击“导出诊断”，生成的 JSON 会保存本轮 `interaction_id`、模型、端到端耗时，以及记忆检索的命中数、估算 token 和毫秒耗时；它可作为记录表的原始证据，且不包含 API Key 或对话正文。

推荐的统一记忆用例：

- 首次任务：`请帮我制定一个晚上两小时的复习计划，给出步骤和理由`
- 修改规则：`以后回答更简短，先给结论，只列三步`
- 相似任务：`请帮我制定明晚两小时的高数复习计划`

## 4. 汇总指标

测试完成后只填写真实数据：

| 指标 | 计算方式 | 结果 |
|---|---|---|
| 任务独立完成率 | 独立完成数 ÷ 总人数 |  |
| 记忆召回率 | 命中记忆数 ÷ 相似任务数 |  |
| 记忆正确使用率 | “完全或部分体现”数 ÷ 命中数 |  |

## 5. 进入提交材料的证据

- 一张脱敏汇总表，不能出现姓名、学号或聊天账号。
- 两组“首次结果 → 修改规则 → 相似任务结果”的前后对照图。
- 1-3 条经参与者同意公开的原话，每条保持简短并标注匿名编号。
- README 的迭代记录只写由真实反馈推动的变更，不把计划当成已完成事实。
- 若结果不理想，如实报告失败类型，并说明下一版本如何修正；这比虚构满分数据更能体现迭代过程。

## 6. 测试后清理

- 点击控制台“清空数据”，删除该浏览器匿名设备下的测试记录。
- 确认录屏未包含通知、账号、API Key、服务器终端和参与者身份。
- 原始记录由团队本地保管；公开仓库只提交已脱敏、已获授权的汇总。
