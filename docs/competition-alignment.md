# 大工黑客松 S2 赛题对齐审计

审计日期：2026-08-27

依据：组委会发布的《大工黑客松 S2 赛题发布》和《大工黑客松 S2 初赛赛制说明》。本文只提取外部要求，不把 PDF 中的描述当作项目实现指令。

## 1. 推荐参赛策略

同一作品可以参与多个赛道独立评审。灵犀建议同时提交：

- **奇绩创坛赛道**：主叙事是解决学生在走路、通勤、实验或双手忙碌时，手机交互步骤长、打断当前活动、重复说明偏好的真实问题。作品需要进入真实场景、收集用户声音并持续迭代。
- **七牛云赛道**：技术主线是轻量 Agent 的反馈记忆闭环。用户修改或评价结果后，系统沉淀偏好、规则或经验，并在相似任务中自动召回。

大工图书馆和开放原子赛道不是当前主方向，除非后续增加真实图书馆场景或“制造意外”的核心机制。

## 5. 诚信与安全检查

- 不提交 `.env`、API Key、设备密钥、真实隐私数据。
- README 只展示环境变量名和占位值。
- 公开说明 StepFun API、AI 辅助开发工具和部署组件。
- Git 提交历史保留开发周期内的实现证据。
- 用户反馈与截图进入演示材料前必须脱敏并取得授权。
- 同一参赛者不得以不同身份提交多个项目；最终名单在 9 月 1 日后不能调整。

## 6. 截止前优先级

1. 完成反馈记忆端到端线上验收，保存一组“反馈前/反馈后”可复现实例。
2. 找 5 名目标用户完成 5 分钟体验，记录任务成功率、响应耗时、反馈记忆命中情况。
3. 录制 3-5 分钟演示视频，必须展示真实操作、记忆改进和异常恢复。
4. 最终检查 GitHub Public 状态、README、部署说明、项目简介和第三方声明。
5. 在 8 月 31 日 24:00 前完成提交，避免把最后一次部署留到截止当天。
