## 今晚或明早从哪里下载

1. 打开电脑，双击项目目录里的 `start_animations.cmd`。
2. 浏览器访问 <http://127.0.0.1:8787/animations.html>，先预览各个动作。
3. 下载“完整 TF 动画包”和已就绪的“配套固件”。灰色入口表示相应文件还未开放，不能当作已安装。

资源留在这台电脑的项目里；稍后可以重新打开页面下载。电脑关机、休眠或本机服务停止时，这个本地网址不可访问。

GIF 是预览文件。板子实际读取 `.lxaf` 动画帧包，不是直接播放 GIF 或 MP4。

精修版的网页高清动画单独保留绒毛与五官细节，板端仍使用 128 × 128 的资源。包内的高清预览留在电脑即可；卡上文件名继续使用 `lingxi/animations-v1.lxaf`，这是既有固件要求的文件名，不代表拿到了旧版素材。以下载页显示的资源版本为准。

## 第一次先更新配套固件

你已有的旧版固件不会自动识别 TF 动画。需要先进行一次应用更新，之后再安装动画。

本项目提供 `tools/tf_animation_flash.ps1`。该脚本只写应用到 **`0x10000`**，保留原有 NVS 配网信息和分区表；随后使用 `verify_flash` 对同一地址和同一文件做校验。它不会擦除整片 Flash、不会格式化 TF 卡，也不会修改模型密钥。

这个脚本用于从既有灵犀固件升级。原始小智完整备份、bootloader、partition-table 都不能当作应用文件交给它，也不能把本次应用写到 `0x0`。

### 先准备好

- 用数据线连接板子的 **UART** 接口。
- 关闭 ESP-IDF Monitor、串口助手等正在占用串口的窗口。
- 在 Windows 设备管理器确认本次端口编号，例如 `COM12`；重插后可能变化。
- 将配套固件 ZIP 完整解压，保留 `flash.cmd`、`tf_animation_flash.ps1`、`lingxi-tf-animation.bin` 和 `SHA256SUMS.txt` 在同一文件夹。

### 在解压后的文件夹运行

双击解压后的 **`flash.cmd`**，根据提示输入端口编号即可。也可以在文件夹空白处打开 PowerShell，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tf_animation_flash.ps1
```

脚本会要求输入当前 `COM` 端口，只接受例如 `COM12` 这样的编号。它优先使用本机已有的 ESP-IDF Python：

`D:\Espressif\python_env\idf5.4_py3.11_env\Scripts\python.exe`

否则尝试 PATH 中的 `python.exe`。若提示找不到 Python 或 esptool，请从已安装的 ESP-IDF 环境重新运行；脚本不会自行下载、安装软件。

如果直接使用项目里的脚本，可以显式传入固件路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\tf_animation_flash.ps1 -BinaryPath "实际下载位置\lingxi-tf-animation.bin" -Port COM12
```

把“实际下载位置”换成真实文件夹。如果下载文件名带版本号，以下载后的真实文件名填写 `-BinaryPath`。

默认情况下，脚本会读取固件 `.bin` 同目录的 `SHA256SUMS.txt`，找到与 `.bin` 文件名完全一致的校验值并核对。校验清单存在但格式错误、没有对应文件名或校验不一致时都会停止。

如需显式传入校验值，请从 `SHA256SUMS.txt` 中取 **`lingxi-tf-animation.bin` 那一行**的 SHA-256，在同一命令末尾增加：

```powershell
-Sha256 "SHA256SUMS.txt中对应bin文件的64位SHA256校验值"
```

**下载页“配套固件”的 SHA-256 对应整个 ZIP，不能拿来校验解压后的 `.bin`。**

脚本会先核对文件大小、镜像标记和上述 SHA-256，再检查 esptool 版本与镜像信息；失败会停止。`-WhatIf` 可只查看检查结果和计划操作，**不会连接串口写入**。实际升级时不要加 `-WhatIf`。

只有在写入成功，且随后 `verify_flash` 也成功后，才继续下面的安装步骤。连接失败时检查端口和数据线；不要通过擦除整片 Flash 解决。

## 准备你买的 16 GB TF 卡

使用 **FAT32** 格式。卡里若有文件，请先在电脑备份；本项目不会自动格式化或删除卡内其他文件。你的 16 GB 容量足够本次动画资源。

断电后将 TF 卡插入板子的卡槽，再重新上电。首次先看设备页的 TF 卡识别状态；没有识别成功时，先处理读卡问题，不继续反复下载。

## 方式一：卡留在板子里，让板子联网下载

这个方式不需要读卡器，但必须先更新上面的配套固件。

1. 保持电脑运行 `start_animations.cmd`，让板子连接既有调试网络并能访问这台电脑。
2. 手机连接板子常驻的配网热点 **`LingXi-922C`**，再用浏览器打开 **<http://192.168.4.1/>**。其他板子的热点后缀以屏幕为准；密码沿用现有配网设置。
3. 手机提示“无互联网”是正常的，选择保持连接。先确认新版设备页识别到了 FAT32 TF 卡，再点击 **“从电脑安装动画”**。
4. 板子会通过已配置的联网 Wi-Fi，从电脑服务下载动画。保持电脑开机、服务运行和联网。
5. 等下载与完整性校验完成，再检查实际播放结果。下载中不要拔卡或断电。

这里的“从电脑安装动画”是板子设备页的操作；电脑 `127.0.0.1:8787` 页面负责提供资源文件。它们是两个网址。新版固件的 AP 与已配置的联网 Wi-Fi 同时工作，手机连配网热点时，板子仍通过原有联网 Wi-Fi 向电脑取文件，无需另找板子的 STA IP。

板子保存的服务地址使用电脑的局域网地址，不能填 `127.0.0.1`。动画安装沿用这个地址，不必改动原有的配网和服务设置。

普通 USB 连接暂不会把板子里的 TF 卡显示成 U 盘。无需把模型 API Key 填进这个动画安装流程。

## 方式二：使用读卡器复制

1. 将 TF 卡通过读卡器接到电脑，确认格式为 FAT32。
2. 下载并解压“完整 TF 动画包”。
3. 将动画文件放到卡根目录的这个位置：

```text
TF 卡根目录/
└─ lingxi/
   └─ animations-v1.lxaf
```

例如电脑将卡分配为 `E:`，目标就是 `E:\lingxi\animations-v1.lxaf`。不要多套一层 ZIP 文件名文件夹；不要把压缩包本身直接复制后当作已解压。

4. 安全弹出卡，断电后插回板子，再重新上电。
5. 确认资源校验通过，并观察待机和思考等已接入状态的动作。

## 本次动画会怎样显示

动画包提供每个角色的六类动作预览。当前固件优先保证正常录音和对话：待机、思考时尝试按约 83 毫秒一帧播放；录音时保持姿态，语音回复时仅顶部小头像尝试每 250 毫秒取一帧。如果单次头像绘制耗时超过 10 毫秒，会暂停动画，优先保障声音播放。

上述时间是固件调度目标，实际表现取决于插卡后的读卡与播放结果。安慰、庆祝等动作已经在资源包中；本次不承诺六类动作都已经接入对话语义并自动触发。

## 安装后检查什么

- TF 卡可以识别，资源文件可通过完整性校验。
- 角色五官、胸前校标和透明边缘正常，没有错帧或花屏。
- 对话文字保持清晰，录音和声音播放没有明显断音。
- 已接入的待机、思考和语音头像切换正常，错误提示可以重试。

动画资源准备、固件编译检查与真实 TF 卡联调是不同阶段。本次发布的精确文件大小、SHA-256、固件路径与最终验证记录，由下载页和发布说明提供；未完成实板插卡前，不承诺插卡即用。
