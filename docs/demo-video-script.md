# 灵犀挂件初赛演示视频脚本

建议成片：**4 分 30 秒**，1920×1080，30 fps。全程录制真实网页操作；不展示 API Key、服务器终端、账号信息、浏览器通知或未脱敏图片。旁白可原样朗读，模型回答以现场实际结果为准，不补录或伪造界面数据。

## 录制目标

视频必须在一条连续、可验证的链路里证明：

1. 在线演示能把一句校园信息转成服务器保存的任务。
2. 控制台能继续管理同一任务，并看见 Agent 规划、工具、模型和耗时。
3. 用户反馈会被记忆，并在相似后续任务中真实改变行为。
4. 图片理解、语音/设备状态和断网降级都不是静态画面。
5. 网页是当前控制台和数字孪生，不伪装成已经完成的实机。

## 录制前 5 分钟准备

- 用新的浏览器无痕窗口访问 <https://lingxi.rainlei.xyz/demo>，确保匿名访客没有旧记忆。
- 在同一窗口新开 <https://lingxi.rainlei.xyz/console> 标签页；两个页面才会共享该访客的任务与记忆。
- 准备一张无个人信息、文字清楚的校园活动海报或课程通知图片（小于 8 MB）。
- 关闭消息通知、密码管理器、下载栏和其他浏览器标签；音量调到可听见但不刺耳。
- 先确认页面顶部显示“Step 3.7 已连接”。如网络波动，保留“停止等待”和“断网演练”作为真实容错证据，不要重录成假数据。

## 分镜与旁白

### 0:00–0:25｜问题与定位

画面：从 `/demo` 页首开始，缓慢展示“校园短任务 Agent”与活动海报视觉；镜头不要停留在浏览器地址栏的个人信息上。

旁白：

> 走路、通勤、实验或学习间隙时，学生往往只想完成一个很短的任务，却要反复解锁手机、切换应用、说明上下文和偏好。灵犀把高频的短交互交给随身挂件，把配置、任务和记忆留在网页控制台。现在先用网页数字孪生验证完整链路。

画面证据：`LINGXI / ONLINE DEMO`、校园短任务描述、在线演示与控制台两个入口。

### 0:25–1:05｜从现场信息到真实任务

操作：点击“用示例任务开始”，等待流式输出完成。任务卡出现后，展示“下周三 18:30”“提前一小时提醒”等元信息，点击“确认任务”。

旁白：

> 这里不是一张预制效果卡。Agent 先识别信息、规划任务，再把结果写入服务器。用户确认后，这条讲座任务会按明确时间由服务端调度，控制台能继续管理它。

画面证据：步骤条“识别—规划—记住”、真实任务 ID、确认按钮、提醒时间和“已确认”状态。

### 1:05–1:35｜控制台的可观测 Agent 链路

操作：点击“在控制台查看详情”，或切到已打开的 `/console`。展示同一条已确认任务、任务队列、Agent Trace、模型名称和响应耗时。

旁白：

> 演示页负责低门槛体验，控制台负责持续管理。相同匿名访客的任务不会丢失；评委可以看到 Agent 的计划、记忆检索工具、实际模型和端到端耗时。

画面证据：任务中心中的“已确认”任务、`feedback_memory.search`、`task.create`、`step-3.7-flash` 和耗时指标。

### 1:35–2:35｜反馈记忆真正改变后续任务

操作：在控制台输入：

```text
下周五18:30图书馆有校园讲座，请整理成任务卡。
```

任务生成后，对这条结果选择“需要调整”，输入：

```text
以后校园活动都提前一小时提醒。
```

保存后，再输入：

```text
下周三18:30主楼302有校园讲座，请整理成任务卡。
```

等待结果，展示 Trace 的记忆命中、任务卡中的提醒时间及“按记忆偏好”。

旁白：

> 用户的修改不是一次性差评。系统把“校园活动提前一小时提醒”作为相似场景规则保存。第二个讲座任务没有重复写提前时间，但 Agent 检索到了规则，任务卡按记忆偏好排期。用户本次明确设置提醒或说“不用提醒”时，又会优先覆盖这条记忆。

画面证据：反馈成功提示、记忆数量变化、`1 条命中`、token 与检索毫秒数、任务卡“按记忆偏好”。

### 2:35–3:15｜视觉输入

操作：上传准备好的脱敏活动海报，输入：

```text
请概括图片最重要的信息，并整理成一条任务。
```

等待并展示图片预览、模型标识和任务/回答。若海报中含明确时间，可补充“提前一小时提醒我”，展示图片提取时间进入任务卡。

旁白：

> 同一条 Agent 链路支持图片理解。Step 3.7 Flash 读取海报信息，页面展示实际模型与流式结果；明确的时间信息可以进入任务调度，而提醒提前量仍由用户或已授权的偏好决定。

画面证据：图片预览、`step-3.7-flash`、流式回答、图片识别来源和任务元信息。

### 3:15–3:45｜数字孪生与硬件边界

操作：点击“运行设备自检”，展示 OLED 文本、RGB/状态从倾听、思考到回应的变化；滚动到设备协议或硬件准备度。

旁白：

> 当前网页是控制台和数字孪生，不伪装成实机。它已经验证了按键、状态、OLED、RGB、音频和事件协议的语义；下一阶段只需要把同一套事件接到 ESP32-S3 外设。

画面证据：设备自检通过、状态映射、`0.4-draft` 协议和“待联调”标识。

### 3:45–4:12｜异常恢复

操作：开启“断网演练”，提交一条短任务，等待页面给出降级结果并恢复可操作状态；如上游真实响应偏慢，可点击“停止等待”作为补充。

旁白：

> 黑客松现场网络不稳定时，灵犀会清晰说明当前状态、结束等待并恢复输入，而不是卡在思考界面。真实模型与本地兜底保持相同的事件协议。

画面证据：断网状态、兜底提示、输入恢复可用；不要把断网演练的结果说成真实模型输出。

### 4:12–4:30｜收尾与入口

画面：回到 `/demo`，依次露出 `/demo`、`/console`、公开 GitHub 仓库地址和持续升级路线。

旁白：

> 灵犀已经具备可运行、可体验、可验证的反馈记忆 Agent 闭环：从校园现场信息到任务执行，再从用户反馈到下一次更合适的行为。网页端会持续作为真实挂件的控制台，下一步完成实机联调和更多校园用户验证。
