# 灵犀挂件初赛演示视频脚本

建议成片：4 分钟，1920×1080，30 fps。全程录制真实网页操作，不展示 API Key、服务器终端、个人账号或未脱敏数据。

## 0:00-0:25 真实问题

画面：控制台首页与挂件数字孪生全景。

旁白：

> 走路、通勤、实验或学习时，我们经常只想快速完成一个短任务，但解锁手机、切换应用、重复说明偏好会打断当前活动。灵犀由随身挂件、Agent 编排服务和网页控制台组成；网页端现在验证完整链路，后续继续管理真实硬件。

画面证据：页首“校园短任务”描述、Step 3.7、StepAudio、反馈记忆 Agent 和 ESP32-S3 待联调状态。

## 0:25-1:10 Agent 任务闭环

操作：点击“生成复习计划”。

旁白：

> 用户输入任务后，Agent 先规划，再调用反馈记忆检索工具，最后通过 Step 3.7 生成结果。计划、工具、模型和耗时都能在控制台观察。

画面证据：Agent Trace 的四步计划、`feedback_memory.search`、Step 3.7、流式回答和响应耗时。

## 1:10-1:55 反馈沉淀

操作：在结果下选择“需要调整”，输入：

```text
以后回答更简短，先给结论，只列三步
```

旁白：

> 这不是一次普通的差评。用户的修改会变成一条可检索规则，同时记录作用域、使用次数和成本指标。

画面证据：“已沉淀为反馈记忆”、反馈记忆数量从 0 变为 1。

## 1:55-2:35 相似任务召回

操作：输入“请帮我制定明晚两小时的高数复习计划”。

旁白：

> 第二个任务与第一次相似，系统自动召回刚才的规则。控制台显示命中条数、检索耗时和估算 token，结果按要求先给结论并只列三步。

画面证据：`1 条命中`、token 数、毫秒耗时和三步结果。此处停留 3 秒便于评委核对。

## 2:35-3:05 多模态与语音

操作：上传一张不含个人信息的校园标识或资料截图，提问“请概括图片中最重要的信息”。

旁白：

> 同一条 Agent 链路支持图片理解、语音输入和语音播报。Step 3.7 负责多模态理解，StepAudio 2.5 负责语音识别和合成。

画面证据：图片预览、模型标识、流式答案和挂件播报状态。

## 3:05-3:30 硬件路径

操作：点击“运行设备自检”，缓慢滚动到系统架构和硬件接入准备度。

旁白：

> 当前网页是数字孪生，不伪装成实机。0.4-draft 协议已经约定按键、16 kHz PCM、心跳、OLED、RGB 和音频事件；下一阶段把网页输入输出替换为 ESP32-S3 外设。

画面证据：OLED/RGB 状态变化、协议版本和 3/5 硬件准备度。

## 3:30-3:50 异常恢复

操作：开启“断网演练”，再次提交短任务。

旁白：

> 黑客松现场网络不稳定时，系统会快速给出明确反馈、结束等待并恢复可操作状态，不会卡在思考中。

画面证据：断网状态、兜底回复、控制台恢复待机。

## 3:50-4:00 收尾

画面：持续升级路线与在线地址。

旁白：

> 灵犀已经是可运行、可体验、可验证的反馈记忆 Agent。下一步是完成真实挂件联调，并用校园用户反馈继续迭代。

片尾文字：项目名、公开 GitHub 仓库、在线 Demo、参赛赛道“奇绩创坛 / 七牛云”。

## 录制前检查

- 使用新的匿名浏览器会话，确保反馈记忆初始为 0。
- 关闭系统通知、聊天窗口和密码管理器弹窗。
- 准备一张已脱敏、文字清楚、尺寸小于 8 MB 的图片。
- 保持“自动播报”开启，提前确认麦克风和扬声器音量。
- 预演一次断网开关，正式录制后清空测试数据。
- 导出 1080p MP4 并完整观看一遍，确认声音、字幕和鼠标位置清晰。
